01
Chart selection

Match the visual to the relationship in your data

SCRIPT: "The first question is not 'what looks cool?' It is 'what relationship am I showing?' Comparison, trend, composition, distribution, or relationship? Each has optimal chart types."

Bar & Column Charts

The workhorse of comparison

When to use

Comparing categories. Branch performance, product revenue, budget vs actual. Works with 3-15 categories.

Best practices

• Start Y-axis at zero
• Sort by value (largest first) unless alphabetical is needed
• Use horizontal bars for long category names
• One color unless highlighting a specific item

Common mistake: Starting the Y-axis at a non-zero value makes small differences look dramatic. Always start at zero for bar/column charts.

SCRIPT: "Bar charts are simple but powerful. The key rule: start Y-axis at zero. If you start at ₱900K instead of zero, a difference between ₱950K and ₱1M looks massive — but it's only 5%. That's misleading. Always zero baseline for bars."
Line Charts

The storyteller for trends

When to use

Showing change over continuous time. Monthly revenue, daily cash, quarterly growth. Best with 5+ time periods.

Best practices

• Use consistent time intervals
• Limit to 3-4 lines maximum
• Label directly instead of legends when possible
• Show reference lines for targets or averages

Common mistake: Too many lines on one chart. If the viewer cannot distinguish them, split into multiple charts or use a small-multiples layout.

SCRIPT: "Line charts are for TIME. Dili siya for comparing categories. If you have 10 product lines over time, that's 10 lines — too many. Use small multiples: separate small charts for each, same scale, easy to compare."
Pie Charts

Use sparingly and carefully

When acceptable

Showing parts of a whole with MAX 5 slices. The total must equal 100%. Example: revenue by 4 business segments.

When to avoid

• More than 5 categories (use stacked bar instead)
• Comparing values (humans are bad at comparing angles)
• Showing change over time
• Multiple pie charts side by side

Professional tip: Many data visualization experts avoid pie charts entirely. A horizontal bar chart sorted by value is almost always clearer.

SCRIPT: "I'll be honest: most experienced data professionals avoid pie charts. Why? Because humans are terrible at comparing slice sizes. A bar chart is almost always clearer. If you use pie, maximum 5 slices and the total must be 100%."
Tables

When exact numbers matter more than shape

  • Use tables when: The audience needs exact values, not patterns
  • Financial statements: Income statement, balance sheet, trial balance
  • Best practices: Right-align numbers, use thousand separators, highlight variances
  • Conditional formatting: Color-code positive/negative, above/below target
  • Keep it small: If more than 20 rows are needed, add filtering or drill-down
SCRIPT: "Tables are not inferior to charts — they serve a different purpose. When an auditor needs the EXACT number, a chart is insufficient. When a manager needs to spot the TREND, a table is slow. Use both where appropriate."

02
Design principles

Clarity, accuracy, and context

SCRIPT: "Good visualization follows principles. We don't just make pretty pictures. We communicate truth clearly."
Principle 1

Data-ink ratio: maximize data, minimize decoration

  • Remove unnecessary gridlines, borders, and 3D effects
  • Use color purposefully, not decoratively
  • Every pixel should represent data or essential context
  • White space helps readability — don't fill every corner
  • Ask: "If I remove this element, does the message change?"

Edward Tufte's rule: "Above all else, show the data."

SCRIPT: "Edward Tufte, the father of data visualization, introduced the data-ink ratio concept. Maximize data, minimize non-data ink. Remove gridlines that don't help. Remove 3D effects that distort. Remove borders around charts. Let the DATA be the focus."
Principle 2

Color with purpose

Use color to:

• Highlight the most important data point
• Show categories consistently
• Indicate status (green/yellow/red for targets)
• Guide attention to exceptions

Avoid:

• Rainbow palettes with no meaning
• Red/green for colorblind users (use shapes too)
• More than 5-6 distinct colors per chart
• Dark backgrounds that strain eyes

SCRIPT: "Color is a signal. If everything is colorful, nothing stands out. Use muted colors for context and one strong color for the key message. Remember: 8% of men are colorblind, so never rely on color alone. Add shapes or labels."
Principle 3

Context makes data meaningful

  • Comparison: Show vs. last year, vs. budget, vs. target
  • Trend: Is the current value going up or down?
  • Benchmark: How does this compare to industry average?
  • Labels: Title, axis labels, data source, last updated
  • Annotation: Call out significant events or anomalies
SCRIPT: "A number alone is meaningless. '₱4.5M revenue' — is that good or bad? Compared to what? Add context: vs. target (₱4M, so we're ahead), vs. last year (₱3.8M, so we grew), vs. budget (₱5M, so we're behind). Context creates meaning."
Common Mistakes

Misleading visualizations to avoid

Truncated axis

Bar chart not starting at zero exaggerates differences.

Cherry-picked time

Showing only favorable periods hides the full story.

Dual Y-axes

Two scales on one chart create false correlations.

3D effects

Distort proportions. Back slices in pie appear smaller.

Missing labels

No source, date, or definition. Unverifiable claim.

Too much data

50 series or 100 data points. No one can read it.

SCRIPT: "These are not just aesthetic issues — they're INTEGRITY issues. As accountants, presenting misleading data (even unintentionally) damages credibility and can lead to bad decisions. Always ask: could someone misinterpret this?"
Dashboard Layout

Information hierarchy for one screen

  • Top-left: Most important KPIs (big numbers/cards)
  • Top-right: Status indicators or alerts
  • Middle: Trend charts showing change over time
  • Bottom: Detail tables or comparison charts
  • Filters: Date range, branch, category at the top
  • Maximum: 6-8 visual elements per dashboard page
SCRIPT: "People read left-to-right, top-to-bottom. Put the MOST IMPORTANT information top-left. Think like a newspaper: headline first, details below. Maximum 6-8 charts per page — if you need more, create multiple pages."
Dashboard for CFO

Example: executive financial dashboard

Top row (cards)

Revenue MTD, Net Income, Cash Balance, A/R Overdue — each with vs. target indicator

Middle (trends)

Revenue trend (line), Cash flow forecast (area), Budget vs Actual (bar)

Bottom (details)

Top 5 overdue customers table, Expense by category bar, Branch comparison

Filters

Period selector, branch filter, segment filter — applied globally to all charts

SCRIPT: "A CFO dashboard should answer in 10 seconds: Are we making money? Do we have cash? Are we on budget? Where are the problems? That's it. Details are for drill-down, not the main view."
Walkthrough

Building a simple dashboard (generic steps)

  • 1. Connect data source: Import CSV, connect to cloud database, or link spreadsheet
  • 2. Clean and model: Remove blanks, fix types, create relationships between tables
  • 3. Create measures: Define calculations (total revenue, running average, YoY growth)
  • 4. Build visuals: Add charts one by one, test with real data
  • 5. Add context: Titles, filters, comparison lines, conditional formatting
  • 6. Review: Check accuracy against source, test with stakeholders
SCRIPT: "This process works regardless of tool — Power BI, Looker, Tableau. The sequence is: data first, model second, visuals third, context fourth, review last. Never start with the chart before understanding the data."
Trust Indicators

Making dashboards trustworthy

Data source

Show where the data comes from.

Last refresh

Show when data was last updated.

Definitions

Define key terms (what's included in 'revenue'?).

Owner

Who maintains this dashboard?

Reconciliation

Does the dashboard agree with official reports?

Version

Mark draft vs published dashboards clearly.

SCRIPT: "If a manager sees a number and asks 'where did this come from?' and nobody can answer, trust is broken. Always show: data source, last refresh time, and definition. That's the minimum for a trustworthy dashboard."

Recap

Visualization principles to remember

  • Choose charts based on the DATA RELATIONSHIP, not aesthetics
  • Start bar chart axes at zero. Limit pie charts to 5 slices.
  • Use color with purpose — highlight, don't decorate
  • Context (comparison, trend, benchmark) makes data meaningful
  • Dashboard layout: most important top-left, max 6-8 visuals
  • Trust = source + refresh time + definitions + reconciliation
SCRIPT: "Visualization is communication. Every chart you create should answer a question clearly and honestly. When in doubt, simplify. A clear simple chart beats a complex confusing one every time."
